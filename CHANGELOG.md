# Changelog

## Unreleased

- Settings view: `settings` (or the tray icon's Settings) lists every setting by group, and Enter changes the selected one: toggles flip, choices step, text and numbers edit in place, lists (exclusions, web shortcuts) edit one entry per line. Each change is written to config.toml with toml_edit, so your comments and layout stay, a value set back to its default is removed, and a change that would make the file invalid (a bad hotkey, a prefix used twice, a zero count) is refused with the reason.
- config.toml applies without a restart: Seekr checks it every two seconds and applies what changed (the hotkey is re-registered, web shortcuts rebuilt, the AI's models and idle time picked up, and the indexer runs a full pass when exclusions or the battery setting change). A file with an error keeps the settings Seekr had, and the settings view says what is wrong.
- New settings: `exclude` (folder paths, or names that match any part of a path, left out of file results, content results, AI passages and content indexing), `[tools]` (turn the calculator, clipboard history, window switcher, system commands, web, emoji, notes and to-dos, or AI off; clipboard history then stops recording), `[prefixes]` (the words for the clipboard, window, emoji, note and to-do lists), `clipboard_days` and `clipboard_entries`, `ai_idle_minutes`, and `embed_on_battery`.

- AI answers about your files: `?` and a question (or "Ask AI") gives about 3,000 tokens of the best-matching passages (by words and meaning) to the model, numbered, and the answer streams into the preview pane citing them; a citation or source opens its file. A follow-up keeps the earlier passages first, adding new ones after, so the model's prompt cache still holds them; Esc stops an answer. The default model is Qwen3.5-4B (Q4_K_M) in llama.cpp's server on the GPU, chosen by benchmark (`docs/benchmarks/llm.md`): it starts on the first question (2.1 s), answers in about 0.15 s to the first word with fixed passages, stops after ten idle minutes, and runs inside a job object so it ends with Seekr even if Seekr crashes; the GPU goes back to its low-power state. It accepts requests only with a key generated at each start. Questions about files never leave the PC. The model files aren't installed by `install.ps1`: the first `?` offers to download them (below).
- Summarize with AI: an action on files Seekr can read (text, Markdown, code, notebooks, RTF, Word, PowerPoint, Excel) gives that file's text (up to 16,000 characters, cut at a line break and marked as cut) to the local model and streams a summary; `?` follow-ups ask about the same file without searching again. README.md (5,900 characters) is summarized in 0.7 s to the first word and 3.6 s in all.
- Phase 5 gate met through Seekr's own code (`phase5_gate` test): with about 3,000 tokens of passages, 3.8 s to the first word from cold, 0.54–0.76 s warm, 79 tokens/s, 4.0 GB on the GPU, and the GPU back in P8 4.3 s after the model stops (`docs/benchmarks/llm.md`).
- Local AI setup: until the model is installed, the `?` row's Enter opens a download screen listing the CUDA runtime (424 MB), llama.cpp b11819 (160 MB) and Qwen3.5-4B Q4_K_M (2.7 GB), with progress for each, the space needed while installing and once installed, and the free space on the drive (it won't start without enough). Each download is checked against its SHA-256 and thrown away if it doesn't match; the zips are unpacked with Windows' own tar and deleted. Esc stops it; what finished stays installed. Downloading and unpacking llama.cpp took 17.5 s here.
- General AI questions: `??` and a question goes to a cloud model, Groq (`openai/gpt-oss-120b` by default, tried first) or Gemini (`gemini-3.5-flash`), with only the question (and the earlier `??` turns) sent: no files, no search. It uses whichever key is in your user environment (`GEMINI_API_KEY` or `GROQ_API_KEY`, read at each question, so no restart is needed after setting one); `api` in config.toml picks one when both are set and `api_model` the model. Until a key is set, the row says which variables to set. Switching between `?` and `??` starts a new conversation.
- Notes and to-dos, as Markdown in `Documents\Seekr Notes` (always in content search, so searchable by words and meaning). `note <text>` saves a note named for its date and first words; `note` lists recent ones, and Edit here (under Tab) edits one in the preview pane: Ctrl+S saves (written beside the note and renamed over it), Esc cancels. `todo <task>` adds to `To-dos.md`, reading a due date off the end (`by friday`, `tomorrow`, `on 2 nov`, `2027-01-15`); `todo` shows the checklist, soonest due and overdue first, then recently done. Enter marks done or not done; Delete is under Tab. "Notes" and "To-dos" type the prefixes for you.
- Emoji and symbols: `:` or `emoji ` and a few words (`:fire`, `:thumbs up`, `:indian rupee`, `:rightwards arrow`, `:greek pi`) finds emoji up to Unicode 16 (what Windows 11's emoji font draws) by name, CLDR keyword and GitHub shortcode, and symbols by name: currencies, arrows, math, punctuation, Greek letters, fractions, check marks and stars. Names and keywords come from Unicode CLDR 48 (`app/src-tauri/data/cldr-annotations.txt`). Enter pastes into the window you were in (copies for an admin window), Ctrl+Enter copies, and emoji that take skin tones list the five under Tab. "Search emoji & symbols" types the prefix for you.
- The web: shortcuts search a site with the words after them (`g`, `ddg`, `b`, `yt`, `gh`, `wiki`, `maps`, `amz`, `so`, `r`, `npm`, `crates`, `mdn`, `imdb`, `tr`), and `[shortcuts]` in config.toml adds or replaces them (`jira = "https://example.atlassian.net/browse/%s"`). Every query ends with "Search the web for …" on the engine `search` names (Google by default). Bookmarks from Brave, Chrome and Edge, across all profiles, rank with apps; the five history pages that best match (visits fading with a two-week half-life) come just before the web search. Browser data is read in the background when the panel opens, at most every five minutes (61 bookmarks and 5,003 history entries here in 157 ms), from copies of the History databases taken with full sharing so the browsers keep running; the copies are deleted at once and nothing is stored or logged.
- System controls, searchable like apps: Lock, Sleep, Restart, Shut down and Sign out (the last three ask for a second Enter); Volume up/down and Mute; Brightness up/down (the built-in panel through WMI, external monitors over DDC/CI, on a worker that applies only the last of a burst); Turn Wi-Fi or Bluetooth on or off; Switch dark and light mode (apps and Windows together); Empty Recycle Bin (confirmed); Close frozen apps (confirmed); and 106 Windows Settings pages ("bluetooth settings", "startup apps settings"). `volume 40` and `brightness 70` set a level directly. Each command reports what it did in a small toast. The window switcher marks windows that aren't responding and offers End task for them.
- Window switcher: `win ` lists the windows Alt+Tab would show, most recently used first, with their program's icon; words after it match the title or program name. It follows Alt+Tab's rules (a window's root owner and last active popup), so tool windows, no-activate windows, cloaked windows (other virtual desktops, suspended Store app frames) and untitled ones are left out. Enter switches (restoring a minimized window); Minimize and Close window keep the list open. Admin windows can be switched to but not closed from Seekr, which says so. "Switch windows" types the prefix for you.
- Clipboard history: Seekr keeps what you copy (text with its formatting, images and files) in `%LOCALAPPDATA%\Seekr\clipboard.db`, images as PNGs in `clips\`, for 30 days or 1,000 entries; pinned entries stay until unpinned. Type `clip ` and a few words, or run "Clipboard history". Enter pastes into the window you were in (focus goes back to it first), Ctrl+Enter copies, and the actions add Paste as plain text, Pin and Delete. Copies a password manager marks as private (`ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0, `Clipboard Viewer Ignore`) are never read. A copy of the same thing moves the old entry to the top instead of adding another. Windows doesn't let a normal app type into an admin window, so pasting into one leaves the entry on the clipboard and shows a "Copied — press Ctrl+V" note.
- Calculator and converters: a query that evaluates shows its result first, and Enter copies it. Math, units, number bases and percentages come from fend (`5 km to miles`, `255 to hex`, `150 + 18%`, `20% of 150`); currencies use the ECB's daily rates and convert to rupees unless you name a target (`10 usd`, `250 gbp to eur`, `₹500 to usd`); time zones take cities and abbreviations (`time in tokyo`, `3pm ist to pst`); and date math counts days and weekdays (`today + 30 days`, `days until 25 dec`, `3 weeks from tomorrow`). Rates are fetched from frankfurter.dev over Windows' own TLS only after a currency is typed and the cached copy (`%LOCALAPPDATA%\Seekr\rates.json`) is over a day old, so conversions work offline. Long results are rounded (2 places for money, 4 otherwise) and say so. Calculations are neither logged nor kept as recent results. Keystroke to painted results while typing calculations: p95 15.0 ms.
- Meaning search: content results also find passages that mean what you typed (four characters or more), not just the same words. The indexer embeds each passage with gte-modernbert-base (picked by benchmark, see `docs/benchmarks/embeddings.md`); the app embeds the query with the int8 weights on the CPU and ranks every passage by cosine after subtracting the mean passage vector, which keeps word lists, minified code and subtitles from matching every query. Word and meaning results are merged by reciprocal rank fusion. `scripts\install.ps1` downloads the model (about 750 MB, pinned revision, SHA-256 checked) to `%LOCALAPPDATA%\Seekr\models`. Measured on about 1,000 files (9,065 passages): first embedding 5.6 min on the RTX 5050 (DirectML), a saved file searchable by words and meaning 2.3 s after the save, content results p95 66 ms while typing, file results p95 25.5 ms.
- Embedding runs in bulk on the discrete GPU through DirectML (the adapter with the most dedicated memory, 2 GB or more), at idle CPU priority, and drops the model when done so the GPU goes back to its lowest power state. A few changed files are embedded on the CPU. Bulk embedding waits while the laptop is on battery and catches up within a minute of mains power returning (90 deferred passages: 22 s from plugging in to searchable).
- Content results open the preview at the matching line, with line numbers, the line marked and the query's words highlighted; the subtitle names that line.
- "Pause content indexing" / "Resume content indexing" in Seekr's commands, with what the indexer is doing now (files checked, or passages embedded out of the total). Paused, nothing is read; resuming catches up on everything that changed.
- The query model loads when the panel opens (about 0.5 s, in the background) and is dropped 30 s after the last search, so idle memory stays at about 250 MB for all processes.
- Content search by words: `seekr-indexer.exe` (installed next to Seekr) reads the chosen folders at background priority into a Tantivy full-text index in `%LOCALAPPDATA%\Seekr\content`, then exits. It runs once at launch and again within half a second of a file being saved, created or deleted there. It reads text and code, Markdown, Jupyter notebooks, RTF, Word, PowerPoint and Excel files (no PDF text yet), honours `.gitignore`, skips hidden and junk folders (`node_modules`, `target`, `build`, `dist`, virtualenvs and so on), links, online-only OneDrive files and anything over 4 MB of text, and quarantines a file that crashed or hung a run (30 s) until it changes. Results appear after the file names with the matching line and text, every word required (with stemming), and support `"phrases"` and `-exclusions`. Measured: about 1,000 files indexed in 16–23 s, a saved file indexed 0.5 s later, content results p95 25 ms, file results p95 27.6 ms, all processes 235 MB private working set when idle.
- Content search folders: the first time the panel opens it asks which folders Seekr may read for content search. Desktop, Documents and Downloads (where Windows really keeps them, often in OneDrive) and common code folders are suggested, none ticked; Ctrl+O adds any folder. The choice lives in `%LOCALAPPDATA%\Seekr\content-folders.txt`, the notes folder (`Documents\Seekr Notes`) is always included, and folder results gain "Add to content search". "Choose content search folders" reopens the picker. Nothing is indexed yet; the indexer comes next.
- Fixed: the index service handed out its startup snapshot even after the USN journal no longer reached back to it, so a client starting without a cache got a stale index and an error every 30 s. It now takes a fresh snapshot when that happens.
- Faster file search on short queries: a 4-byte letter mask per name (rebuilt at load) and a byte-level check skip names that can't match before nucleo scores them, and large sets are ranked with a quick score whose best 300 nucleo re-scores. Full scans of 2 million names for two or three letters dropped from 12–19 ms to 9–10 ms; file results while typing are p95 29.3 ms. File search also starts before apps are ranked, and journal changes no longer reset the typing cache.
- Previews for files and folders: highlighted code and text (UTF-8 or UTF-16, first 64 KB), Markdown (raw HTML is dropped and links don't navigate), the text of Word, PowerPoint and Excel files, folder listings, and shell thumbnails for images, video and PDFs where Windows has a thumbnail handler. Cloud-only files are never read, so previewing doesn't download them. PDF text needs pdfium, which comes later.
- File actions: Open with…, Copy file (pastes into Explorer as a copy), Copy path, Open in Terminal (Windows Terminal, or PowerShell), Properties, and Move to Recycle Bin, which asks for a second Enter first.
- Alt+F4 or a close message on the panel hides it instead of quitting Seekr; Quit is in the tray and in Seekr's commands.
- File filters: `ext:` `kind:` `folder:` `in:` `dm:`/`modified:` `size:` `"exact"` and `-exclude` (see Search syntax in the README), shown as chips under the search box. Filters alone list the newest matches first, and queries with filters skip app results. Sizes and dates for C: come from a background walk after the service's snapshot (about 24 s); changes are re-read as they happen. The index cache format changed, so the first start after updating rebuilds it.
- File search covers every fixed drive. Drives the service doesn't read (other letters, FAT/exFAT), and C: when the service isn't installed, use a no-admin fallback: a low-priority walk that skips junctions and symlinks (about 21 s for 2.2 million names on C:), then a directory watcher for changes. Each drive is cached in `%LOCALAPPDATA%\Seekr\files-<letter>.idx` and walked again at startup.
- Whole-drive file search: every file and folder name on C: (from the SeekrIndex service) is searchable from the second character typed. One or two characters match as a substring; longer queries are fuzzy. Results favour your Desktop, Documents and Downloads, sink system and build folders, and learn from what you open. New files show up within milliseconds. The index is cached in `%LOCALAPPDATA%\Seekr\files-C.idx`, so restarts take about 0.3 s.
- SeekrIndex service (`seekr-svc.exe`, LocalSystem, installed to `C:\Program Files\Seekr` by `scripts\install.ps1` with one UAC prompt). It reads every file name on C: from the NTFS master file table, writes a snapshot only the signed-in user can read, then streams changes from the USN journal over a pipe only SYSTEM and that user can open. Other accounts' profiles and NTFS metadata files are left out.
- `scripts\install.ps1`: installs the release build to `%LOCALAPPDATA%\Programs\Seekr`, starts it hidden at login and sets the power-saving GPU preference; `-Uninstall` removes all of that and keeps your data.
- WebView2 is asked to use less memory while the panel is hidden.
- Desktop apps get Open file location (Ctrl+Enter), Run as administrator and Copy path; Store apps only open.
- Typing a path (`C:\...`, `~\...`, `%WINDIR%\...`, `\\server\share`) or a URL (`https://...`, `www....`) offers it as the first result, with Open, Show in folder and Copy.
- Esc, the hotkey and copy actions give focus back to the window you were in, and check that Windows did it.
- Ranking: fuzzy matching that favours word starts and acronyms ("vsc" finds Visual Studio Code), boosted by how often and how recently you chose a result for what you typed (14-day half-life). Results can be pinned to the top from the actions list. An empty search shows pins, then recently used results. Usage lives in `%LOCALAPPDATA%\Seekr\seekr.db`.
- Fixed: the first time the panel opened it was a title bar's height too tall.
- `SEEKR_DATA_DIR` overrides the data folder (logs, icons, database), for test runs.
- App search: every Start menu shortcut and Store app (shell:AppsFolder) is searchable by name and launches with Enter. Icons are rendered once into `%LOCALAPPDATA%\Seekr\icons`. The list is rescanned in the background at most once a minute when the panel opens, so new installs appear on the next open.
- If Windows can't report the cursor position, the panel opens on the primary monitor instead of failing.
- Panel layout: results list, preview pane and hint bar. Keys: Up/Down select, Enter runs the main action, Ctrl+Enter the second one, Tab or Ctrl+K lists all actions, Alt+1-9 runs a visible row, Esc closes the actions list or the panel.
- Seekr's own commands are searchable: Open Seekr config (creates a commented `config.toml` if missing), Open Seekr logs, Quit Seekr.
- Every keystroke starts a new query that supersedes older ones; results reach the screen at most once per frame.
- Latency telemetry: hotkey-to-ready and keystroke-to-painted times are logged as p50/p95/max every 50 samples.
- Strict content security policy in release builds.
- Turning Start at login on or off is logged.
- Search panel: a pre-created hidden window with a Mica backdrop that opens on Alt+Space (or the `hotkey` in `config.toml`) on the monitor under the cursor, sized for its DPI. Esc or clicking away hides it.
- Hotkey falls back to a low-level keyboard hook when another app already owns the combination. In that mode the hotkey opens the panel, but pressing it again while the panel is focused reaches the other app instead; use Esc.
- Tray icon with Open, Start at login and Quit. A second launch opens the running panel instead of starting another copy.
- Panics are written to `logs\<name>.panic.log`.
- Project setup: Cargo workspace, Tauri 2 + SolidJS app, `common` crate (paths, config, logs), check and dev scripts.
